# 手机使用指南

Context Relay 手机端用于查看和控制**电脑管理器中已有的任务**：读取回复、明确发送补充指令、暂停、只读核对恢复、处理本次审批或问题，以及整理简报和审核阶段成果。电脑负责运行 Codex，手机不直接连接原生 Codex RPC，也不创建第二个任务库执行者。

当前是原生 Java Android 首版，最低 Android 8.0 / API 26，无 Google 服务依赖。它不直接控制正在官方 Codex Desktop 中运行的聊天。已有聊天先在电脑选择导入；导入只保存历史资料，后续工作进入管理器自己的会话。请先停止原聊天及同项目的其他写入操作，避免两边同时工作。

## 先准备电脑和 APK

1. 按[本机管理器指南](windows-manager.md)准备 Windows、Python 3.10+、Tk 和可用的 Codex 安装与登录。用已有快捷方式或 `python -m relay` 打开管理器，在电脑创建或导入任务。
2. 首次开启手机连接需要 OpenSSL 生成本机证书。程序查找 PATH 及常见 Git for Windows 的 OpenSSL 位置；找不到时会明确报错，不会自动安装或降级到 HTTP。
3. 预览 APK 和 SHA-256 校验文件从 [GitHub Releases](https://github.com/Jsany0619/context-relay/releases) 获取。自行构建时，产物位于 `mobile/android/build/context-relay.apk`，校验文件在同目录。用手机下载或通过自己的可信渠道传输 APK，打开后按 Android 系统提示确认安装；不同系统版本的“允许此来源安装”入口可能不同。

当前 APK 使用仓库外保存的独立本地测试签名，不是应用商店或正式发行身份。相同应用包的升级需要保持签名一致。自行构建、工具要求与签名边界见 [Android 构建说明](../mobile/android/README.md)。不要为解决安装问题先清空应用数据；其中可能有尚未核实的请求记录。

## 首次同 Wi-Fi 配对

1. 手机和电脑连接同一个可互通的 Wi-Fi / 局域网。电脑保持开机，主管理器窗口保持运行。
2. 在主窗口点击 **手机连接**。从“本机地址”选当前实际使用的局域网 IPv4，例如 `192.168.1.20`；这只是示例，须换成自己电脑的地址。`10.x.x.x` 或 `172.16–31.x.x` 也可能是正常局域网地址。`127.0.0.1` 只表示设备自身，不能用于另一台手机连接电脑；不要照搬模拟器地址。
3. 保持默认端口 `8765`，或填写一个未占用的端口。点击 **开启连接并生成配对信息**。网关只在明确开启后监听，不随独立 skill 安装自动开启。
4. 必要时按下一节配置一条精确的 Windows 防火墙规则。
5. 点击 **复制配对信息（5 分钟内有效，仅一次）**，通过可信方式传给自己的手机。完整文本以 `contextrelay://pair#` 开头，包含一次性秘密，不要发到公开聊天、问题报告或截图中。过期或已用时，在电脑点击 **重新生成**。
6. 打开手机 App，粘贴完整文本，点击 **核对并配对**，核对电脑地址及证书 SHA-256，再明确确认。系统已有扫码工具若能打开这种链接，也可使用；App 不内置扫码器，也不请求相机权限。
7. 配对后点击 **刷新任务列表**，选择电脑已有任务。手机不会自动创建、导入或启动任务。

电脑换地址后，先关闭手机连接，再选新地址开启并重新配对。更换证书也必须重新配对。手机只接受 HTTPS，以已配对的精确叶证书指纹和有效期确认电脑身份，并只连接配对地址中的主机；不接受重定向或“忽略证书错误”。这不是公共 CA 对域名或 IP SAN 的认证。

## Windows 防火墙：先预览，按需开启

仓库提供 [Set-PhoneFirewall.ps1](../mobile/Set-PhoneFirewall.ps1)。脚本不关闭防火墙，只管理本项目一条与**实际 Python 程序路径、本机 IP、端口**绑定的入站 TCP 规则。局域网来源限制为 `LocalSubnet`；私有网络地址 `100.64.0.0/10` 使用该网段作为来源范围。已有规则若被修改或名称冲突，脚本拒绝替换。

在仓库根目录打开 PowerShell，先按自己的电脑填写变量。快捷方式通常使用 `pythonw.exe`，控制台启动通常使用 `python.exe`；务必与本次管理器进程实际使用的程序一致，不能只按同名程序猜测。

```powershell
$relayIp = '192.168.1.20' # 替换为手机连接窗口选中的真实本机地址
$relayPort = 8765
$relayPython = (Get-Command pythonw.exe).Source # 核对快捷方式目标；控制台启动则使用实际 python.exe
.\mobile\Set-PhoneFirewall.ps1 -Action Preview -LocalAddress $relayIp -Port $relayPort -PythonPath $relayPython
```

`Preview` 不需要管理员权限，也不改规则。审阅输出的程序、IP、端口和来源范围。只有确需放行时才在**管理员 PowerShell**中进入同一仓库目录、重新设置上述变量并执行：

```powershell
.\mobile\Set-PhoneFirewall.ps1 -Action Enable -LocalAddress $relayIp -Port $relayPort -PythonPath $relayPython
```

不用这条规则时，以管理员身份用**相同参数**精确移除：

```powershell
.\mobile\Set-PhoneFirewall.ps1 -Action Remove -LocalAddress $relayIp -Port $relayPort -PythonPath $relayPython
```

脚本会检查地址确实属于本机，不会自动提权或修改 PowerShell 全局执行策略。如果组织策略不允许脚本运行，应由系统管理员按预览结果管理规则，不要关闭整机防护绕过。

## 日常对话与审批

手机输入先保留为按电脑和任务区分的草稿。只有点击 **明确发送 / 启动或继续** 并确认本次操作后才会提交；语音键盘听写也只是可编辑草稿。电脑确认接收后，只清除与本次发送完全相同的原草稿，之后新输入的文字保留。执行中不能再启动一轮，可以先保存草稿、明确暂停、核对结果，再继续。

较大字体或键盘打开时，任务页面和弹窗内容可以上下滚动；编辑框滚到内容边缘后可继续滚动外层页面。顶部状态说明若被折叠，可点按查看全文。

收到回执后，先看它属于“已接收、处理中、命令已处理、失败还是未知”。**电脑已处理启动命令，不等于模型已经完成任务。** 点“已读此确定结果，返回任务”后刷新任务状态和最新回复。退出手机 App 不会暂停电脑任务；需要停止工作时先明确请求暂停，等待电脑确认。

审批页面展示实际命令或文件变更，只能允许或拒绝**本次**请求。详情缺失、截断或不支持时不能允许；问题中的密码、密钥等秘密字段不在手机收集。手机不会提高任务原有的只读 / 项目可写权限范围。

简报与阶段审核按需生成，会消耗模型用量。空目标任务首次启动先生成只读简报，须检查并采用后再工作。**采用简报和人工认可阶段结果只保存决定，不启动工作；“按审核意见启动返工”会在明确确认后启动一轮核对和返工，消耗模型用量。** 返工仍受原权限和预算约束。AI 意见、已有测试报告、独立自动化验收和人工认可分别保留；“人工认可本阶段”不等于正式发布验收。

## 断线、未知结果与重新配对

手机在首次发送前密封保存请求编号和内容。超时、应用退出后恢复、重复点击或查询得到 `404`，都不能证明电脑没有执行；手机只查询原编号，不自动换一个编号重发。

若仍显示未知，或设备撤销后查询被拒绝：

1. 先在电脑查看原任务、在途操作、审批和实际产物，必要时使用只读核对恢复。发布、发送、付款等外部动作结果不明时不得重试。
2. 完成电脑端核对后，才在手机明确点击 **已在电脑核对，解除手机等待** 并确认。手机先把原请求编号、内容及已有回执保存到密封历史，再解除当前等待。
3. 解除等待不证明原操作成功，不重新发送原操作；任何后续新动作仍受电脑当前任务状态和版本检查约束。需要重配对时再由电脑生成新信息。

不要用清空数据或卸载 App 代替核对：它们会丢失手机保存的草稿和请求身份。配对时网络中断也可能已经消耗一次性信息，应在电脑核对设备列表并生成新信息，不要假称原配对一定失败。

## 关闭、撤销与网络边界

关闭“手机连接”这个小窗口**不会**关闭连接。停止接收手机指令时点击 **关闭手机连接**；关闭主管理器后也无法继续连接。无需后台服务，但电脑必须保持开机、网络连通和管理器运行。

在电脑设备列表选择设备，点击 **撤销所选设备** 可停止它后续的远程访问。撤销凭据或关闭连接不是撤回已经进入执行的命令；任务若仍在运行，应另外暂停并核对。

首选同 Wi-Fi 完成第一次使用。也可在双方已配置好的私有网络上选择电脑的相应 IPv4 地址，但本项目不代办私有网络服务的账户登录、设备加入或路由设置，**跨网络实际连通未在此作保证**。同 Wi-Fi 方案不需要公网端口映射、公开临时隧道或云中转；不要把本机监听直接暴露到公网。访客 Wi-Fi、无线客户端隔离、VPN 路由、防火墙或电脑休眠都可能阻断连接。

手机凭据、草稿与请求记录使用 Android Keystore 的 AES-GCM 密封，并禁用应用备份与界面截屏。电脑的状态目录仍是本地私密记录；其中包含网关证书私钥和远程操作账本，不要公开上传。私钥继承状态目录的 Windows 访问权限，请使用当前用户的私有本地目录，不要放在共享目录；不能把 `chmod` 当作 Windows ACL 保护的证明。任务备份不包含远程凭据账本，也不能恢复手机执行权限。这些措施不保证抵抗已被完全控制的手机、电脑或同账号进程。

## 验收与故障定位

当前测试范围、版本、APK 哈希和缺口统一见[手机功能验收记录](mobile-validation.md)。主机断言、真实 Android 模拟器、合成模型响应、原生 Codex 执行和 Android 真机结果须分别判断；本指南不把其中一种替代另一种。

连接失败时按顺序检查：主管理器仍运行 → 手机连接已开启 → 使用真实本机 IP 和对应端口 → 两端网络可互通 → 防火墙规则对应当前 `python` / `pythonw` 路径 → 配对信息仍有效。证书不符时返回电脑核对身份，不允许不安全回退。排查资料只提供版本、非敏感错误和发生步骤；不要附配对文本、凭据、密钥或完整任务记录。
