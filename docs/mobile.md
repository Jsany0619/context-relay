# 手机使用指南

Context Relay 手机端用于查看和控制**电脑管理器中已有的任务**：读取回复、明确发送补充指令、暂停、只读核对恢复、处理本次审批或问题，以及整理简报和审核阶段成果。电脑负责运行 Codex，手机不直接连接原生 Codex RPC，也不创建第二个任务库执行者。

当前为原生 Java Android 预览版，最低 Android 8.0 / API 26，无 Google 服务依赖。已有聊天提供两种不同用途：**连接原聊天**保留原生聊天 ID、原话接续；**历史导入**保存资料，再经简报采用进入管理任务。两者都须先停止原聊天及同项目的其他操作，避免两边同时工作。新增原聊天连接与原文页目前是候选功能，实际验收进度见[验收记录](mobile-validation.md)，不能用旧版测试替代。

## 先准备电脑和 APK

1. 按[本机管理器指南](windows-manager.md)准备 Windows、Python 3.10+、Tk 和可用的 Codex 安装与登录。用已有快捷方式或 `python -m relay` 打开管理器，在电脑创建或导入任务。
2. 首次开启手机连接需要 OpenSSL 生成本机证书。程序查找 PATH 及常见 Git for Windows 的 OpenSSL 位置；找不到时会明确报错，不会自动安装或降级到 HTTP。
3. 预览 APK 和 SHA-256 校验文件从 [GitHub Releases](https://github.com/Jsany0619/context-relay/releases) 获取。自行构建时，产物位于 `mobile/android/build/context-relay.apk`，校验文件在同目录。用手机下载或通过自己的可信渠道传输 APK，打开后按 Android 系统提示确认安装；不同系统版本的“允许此来源安装”入口可能不同。

升级构建保留此前 APK 的签名证书身份，以便覆盖安装；私钥保存在仓库外，签名口令改用随机值并由当前 Windows 用户保护。此前证书的名称不能据此改写，也不等于应用商店审核。自行构建、工具要求与签名边界见 [Android 构建说明](../mobile/android/README.md)。不要为解决安装问题先清空应用数据；其中可能有尚未核实的请求记录。

0.2.5 手机端需要配套更新电脑端：在任务安全停稳后，用新版源码重新打开电脑管理器，再覆盖安装 APK。若手机提示更新电脑端，应先更新并重开电脑端；重复配对或清空手机数据不能补齐电脑接口。

## 原话发送到原聊天（候选功能）

1. 在原 Codex 客户端停止该聊天，并停止同项目其他操作。管理器不能跨客户端证明已经停止；预览状态显示“未加载”也不代表原端空闲。
2. 在电脑的已有聊天入口选择来源并预览，核对聊天和项目目录后选择 **连接原聊天**。明确选择 `read-only`（只读）或 `workspace-write`（项目可写），并确认原聊天及同项目操作已停止。不会继承旧聊天审批，也不会替你批准后续请求。
3. 在 **手机连接** 中将这个任务列入设备授权范围；已配对设备不会自动获得新任务权限。手机选择该任务，核对当前是原聊天连接模式。
4. 输入自己的话，点击 **原话发送**，核对确认后发送。该模式保留输入前后的空格和换行，不加管理器目标、简报或续作提示词。连接本身不自动发送；它也不启用自动换聊天。

接续通过独立 App Server 的 `thread/resume` 使用同一个原生 thread ID。**这不等于 Windows Codex Desktop 宿主的实时镜像、输入框同步或对正在运行的桌面聊天远程控制。** 原生聊天仍有其已有上下文和宿主规则；“原话发送”只说明管理器不包装本次输入，不保证模型逐字复述输入或得到与另一宿主完全相同的行为。不要同时在桌面和手机继续同一聊天。

结果未知时按下文先在电脑核对，不重试原操作。任务当前权限、设备仅查看/控制范围、单次审批和版本核对依然生效；手机不能自行提高权限。

## 查看文字原文（候选功能）

手机原文页读取原生聊天中的用户和 Codex 文字，逐页显示；每页最多 **6,000 个字符、8 个条目**，长消息分段并标明位置，不用简报替代文字。历史改变后旧页码会失效，应刷新后再读。本版 `thread/read` 的读取上限为 **16 MiB**；超限或宿主只提供摘要时明确拒绝，需回 Codex 查看。附件、图片和工具执行详情只标明缺口，不声称已完整呈现整段聊天。

原文页的 GET 读取仍须经过固定证书 HTTPS 和设备凭据核验，只能访问电脑明确授权给该设备的任务。原文正文不写入网关操作回执日志，也不写入手机 Vault；页面读取与密封保存的发送草稿、请求记录是不同数据。原生聊天本身仍由 Codex 保存。原文可能包含敏感资料，选择该功能即是明确查看这些文字；不得把私有原文、聊天 ID、任务记录或截图提交到公开 GitHub。复制到其他应用前也须核对接收范围。

看到来源原文不代表发送目标已经改变：**历史导入模式仍走管理任务和简报采用流程**。要直接接续来源，请明确选择连接原聊天，不能仅凭原文页判断。

## 历史导入：整理后交给管理任务

1. 在原 Codex 聊天停止正在进行的工作，同一项目也不要同时有另一聊天在写文件。
2. 电脑打开 Context Relay，点击 **导入已有聊天**，搜索并选中来源，点击预览。
3. 核对项目目录、历史要求和当前成果。补充想法可以留空，不必重新写一遍目标；留空会先整理候选简报，由你采用后再工作。
4. 选择只读或项目可写权限，确认原聊天已停止，导入为待启动任务。导入本身不会启动模型，也不会接管原桌面聊天的现场。
5. 打开 **手机连接**，勾选这个任务并生成新的手机配对授权；新导入任务不会自动对已配对手机开放。
6. 手机选择任务，即可看到可用的历史摘录和后续对话。导入历史可能被截短、附件可能需重新提供；它不代表资料已经重新核验或允许重做历史动作。

## 首次同 Wi-Fi 配对

1. 手机和电脑连接同一个可互通的 Wi-Fi / 局域网。电脑保持开机，主管理器窗口保持运行。
2. 在主窗口点击 **更多 → 手机连接**，进入 **设备与设置**。从“本机地址”选当前实际使用的局域网 IPv4，例如 `192.168.1.20`；这只是示例，须换成自己电脑的地址。`10.x.x.x` 或 `172.16–31.x.x` 也可能是正常局域网地址。`127.0.0.1` 只表示设备自身，不能用于另一台手机连接电脑；不要照搬模拟器地址。
3. 保持默认端口 `8765`，或填写一个未占用的端口，再回到 **配对手机** 开启连接。勾选允许这台手机访问的任务，选择“仅查看”或“查看与控制”再生成配对信息。需要在手机发送和暂停时选 **查看与控制**。默认没有任务被授权；控制权限仍不能突破任务在电脑端设定的项目权限。
4. 必要时按下一节配置一条精确的 Windows 防火墙规则。
5. 点击 **复制配对信息（5 分钟内有效，仅一次）**，通过可信方式传给自己的手机。完整文本以 `contextrelay://pair#` 开头，包含一次性秘密，不要发到公开聊天、问题报告或截图中。电脑上改选任务或权限后，须重新生成对应的配对信息；过期信息会清空并停用复制。已用或过期时，按窗口里的生成按钮取得新信息。
6. 打开手机 App，通过系统锁屏凭据验证后，点击 **粘贴配对信息** 或手动粘贴完整文本，再点击 **核对并配对**，核对电脑地址及证书 SHA-256 后明确确认。粘贴按钮仅在你点击时读取剪贴板，不自动配对。手机必须设置安全锁；离开 App 后再次进入需要重新验证。系统已有扫码工具若能打开这种链接，也可使用；App 不内置扫码器，也不请求相机权限。
7. 配对后选择电脑明确授权的任务。手机不会自动创建、导入或启动任务。设备访问授权七天到期，可在电脑提前撤销；旧版没有任务范围和到期时间的授权升级后失效，需重新配对。

改选任务清除的是窗口中的旧信息，已经复制出去的配对信息在使用或过期前仍按原授权有效。若误发，先关闭手机连接，核对并撤销不认识的已配对设备，等旧信息过期后再开启连接。

电脑换地址后，先关闭手机连接，再选新地址开启并重新配对。更换证书也必须重新配对。手机只接受 HTTPS，以已配对的精确叶证书指纹和有效期确认电脑身份，并只连接配对地址中的主机；不接受重定向或“忽略证书错误”。这不是公共 CA 对域名或 IP SAN 的认证。

## Windows 防火墙：先预览，按需开启

仓库提供 [Set-PhoneFirewall.ps1](../mobile/Set-PhoneFirewall.ps1)。脚本不关闭防火墙，只管理本项目一条与**实际 Python 程序路径、本机 IP、端口**绑定的入站 TCP 规则。局域网来源限制为 `LocalSubnet`；私有网络地址 `100.64.0.0/10` 使用该网段作为来源范围。已有规则若被修改或名称冲突，脚本拒绝替换。

在仓库根目录打开 PowerShell，先按自己的电脑填写变量。快捷方式通常使用 `pythonw.exe`，控制台启动通常使用 `python.exe`；务必与本次管理器进程实际使用的程序一致，不能只按同名程序猜测。

```powershell
$relayIp = '192.168.1.20' # 替换为手机连接窗口选中的真实本机地址
$relayPort = 8765
$relayPython = (Get-Command pythonw.exe).Source # 核对快捷方式目标；控制台启动则使用实际 python.exe
.\mobile\Set-PhoneFirewall.ps1 -Action Preview -LocalAddress $relayIp -Port $relayPort -PythonPath $relayPython
```

`Preview` 不需要管理员权限，也不改规则。审阅输出的程序、IP、端口和来源范围。只有确需放行时才在**管理员 PowerShell**中进入同一仓库目录、重新设置上述变量并执行：

```powershell
.\mobile\Set-PhoneFirewall.ps1 -Action Enable -LocalAddress $relayIp -Port $relayPort -PythonPath $relayPython
```

不用这条规则时，以管理员身份用**相同参数**精确移除：

```powershell
.\mobile\Set-PhoneFirewall.ps1 -Action Remove -LocalAddress $relayIp -Port $relayPort -PythonPath $relayPython
```

脚本会检查地址确实属于本机，不会自动提权或修改 PowerShell 全局执行策略。如果组织策略不允许脚本运行，应由系统管理员按预览结果管理规则，不要关闭整机防护绕过。

## 日常对话与审批

手机输入先保留为按电脑和任务区分的草稿。只有点击 **明确发送 / 启动或继续** 并确认本次操作后才会提交；语音键盘听写也只是可编辑草稿。电脑确认接收后，只清除与本次发送完全相同的原草稿，之后新输入的文字保留。执行中不能再启动一轮，可以先保存草稿、明确暂停、核对结果，再继续。

较大字体或键盘打开时，任务页面和弹窗内容可以上下滚动；编辑框滚到内容边缘后可继续滚动外层页面。顶部状态说明若被折叠，可点按查看全文。

任务详情采用对话列表和底部输入框。电脑明确处理成功的操作回执自动归档，页面继续刷新任务状态和回复，无需先关闭回执。**电脑已处理启动命令，不等于模型已经完成任务。** 执行中的完成消息会陆续显示，未完成的 token 碎片不作为已核验内容显示；新一轮执行不会抹掉上一轮结果。后台或断网时电脑可能继续运行，返回后先解锁并查询已有结果，不自动重新发任务。

任务列表只下载任务摘要和最近回复预览，自动刷新保留阅读位置；打开任务后才读取完整详情。预览不会冒充助手完整回复，详情尚未读到或读取失败时仍可写草稿，但不能发送、暂停或审批。详情成功后才按原有权限恢复操作。

聊天标题保持一行，完整名称和低频功能在右上角“⋯”中查看。输入框与发送按钮并排，暂停和待处理请求按任务状态出现。聊天中的标题、粗体和围栏代码块支持基础排版；代码可横向滚动并点标题旁的“复制”，长按消息边缘可复制完整原文，正文仍可选中文字复制，无障碍操作也提供完整复制。原话模式保留原文字面内容，不执行其中的内容。阅读较早回复时，可以点“最新消息”回到底部；有待处理请求时，页面提供直接入口。复制内容会进入系统剪贴板，粘贴到其他应用前请确认资料可以外传。

手机聊天常态只保留返回、标题、更多、对话和输入发送；暂停、待处理请求、离线、只读和失败提示按当前情况出现。刷新、原始对话与翻页、目标和预算、简报与审核收进“更多”。未确认操作仍在首屏保留可点击提示，打开后查看完整回执、查询或核对；收起信息不会重发操作，也不会清空草稿。

待核对提示显示原操作所属的任务名称和短编号；切换到其他任务不会改变这个归属。旧请求没有保存名称时显示原任务短编号，核对时以回执详情中的请求编号为准。

已有对话有大小上限，被截短时明确提示。审批、简报、阶段审核保留在相关操作入口。手机端提供本项目的任务对话与控制，不包含 ChatGPT 的全部语音通话、图片生成、附件上传或云端工具；手机输入法的语音听写可用，但发送仍由你确认。

审批页面展示实际命令或文件变更，只能允许或拒绝**本次**请求。详情缺失、截断或不支持时不能允许；问题中的密码、密钥等秘密字段不在手机收集。手机不会提高任务原有的只读 / 项目可写权限范围。

简报与阶段审核按需生成，会消耗模型用量。历史导入的空目标任务首次启动先生成只读简报，须检查并采用后再工作；原聊天连接不通过这一步包装手机输入。**采用简报和人工认可阶段结果只保存决定，不启动工作；“按审核意见启动返工”会在明确确认后启动一轮核对和返工，消耗模型用量。** 返工仍受原权限和预算约束。AI 意见、已有测试报告、独立自动化验收和人工认可分别保留；“人工认可本阶段”不等于正式发布验收。

## 外观与偏好

在任务列表或对话右上角点 **⋯ → 外观与偏好**，选择经典蓝／淡绿青、标准／大字、舒适／紧凑间距，再保存。大字选项叠加系统字体大小；紧凑间距保留至少 48dp 的按钮点击区域。恢复默认只调整这三项，取消不保存。

这些选项只保存在本机，不包含账户、对话或控制权限，也不会自动同步电脑。修改外观不会发送消息；草稿、已打开的原文页与待核对操作保持原状态。

## 发送或暂停按钮为什么是灰色

| 手机当前情况 | 原因和处理 |
|---|---|
| 显示“手机仅查看”，发送和暂停都禁用 | 电脑“手机连接”中选中真实任务，改选“查看与控制”，重新生成配对信息；手机重新粘贴并确认。改电脑下拉选项不会升级已经配对的授权。 |
| 有控制权限，但暂停显示“未运行” | 当前没有可暂停的工作；空闲时发送可用，开始运行后暂停才可用。 |
| 项目显示“只读”，但手机有控制权限 | 可以发送消息、讨论和暂停；不能因此修改项目文件。“项目只读”与“手机仅查看”是独立限制。 |
| 离线、待核对或有未确认的操作回执 | 先恢复连接或核对原请求结果。不要通过重配对、清数据或重复发送跳过未知结果。 |

配对仅覆盖当时选择的任务：只授权验收任务，不会自动让手机看到或控制其他项目。原文暂时不可读取或页码已失效，会单独提示；它们本身不代表电脑的任务控制连接已离线。

### 发送失败或运行中自动暂停

任务的分钟上限按**累计运行时间**计算，包括各轮等待模型回复的时间，不是每次发送都会重置。达到时间或 Token 上限后，电脑会自动暂停当前轮次并拒绝再次启动；这是本地任务预算，不是手机断网，也不表示账号余额已经用完。电脑“任务设置”可在任务收束后调整上限；未调整前，重复发送不会恢复运行。

手机收到确定的失败回执时，顶部直接显示具体原因，并保留请求编号和“已读此确定结果，返回任务”入口。先读清原因、处理后再明确发送；失败提示不会被后台刷新覆盖，也不会自动重发。只有看到本轮助手回复，才说明回复已经返回；“电脑已接收操作”只代表启动命令已被处理。

## 断线、未知结果与重新配对

手机在首次发送前密封保存请求编号和内容。超时、应用退出后恢复、重复点击或查询得到 `404`，都不能证明电脑没有执行；手机只查询原编号，不自动换一个编号重发。

若仍显示未知，或设备撤销后查询被拒绝：

1. 先在电脑查看原任务、在途操作、审批和实际产物，必要时使用只读核对恢复。发布、发送、付款等外部动作结果不明时不得重试。
2. 完成电脑端核对后，才在手机明确点击 **已在电脑核对，解除手机等待** 并确认。手机先把原请求编号、内容及已有回执保存到密封历史，再解除当前等待。
3. 解除等待不证明原操作成功，不重新发送原操作；任何后续新动作仍受电脑当前任务状态和版本检查约束。需要重配对时再由电脑生成新信息。

不要用清空数据或卸载 App 代替核对：它们会丢失手机保存的草稿和请求身份。配对时网络中断也可能已经消耗一次性信息，应在电脑核对设备列表并生成新信息，不要假称原配对一定失败。

## 关闭、撤销与网络边界

关闭“手机连接”这个小窗口**不会**关闭连接。停止接收手机指令时进入 **设备与设置 → 关闭手机连接**；撤销设备、网络检查和使用说明也在这个页面。关闭主管理器后无法继续连接。无需后台服务，但电脑必须保持开机、网络连通和管理器运行。

在电脑设备列表选择设备，点击 **撤销所选设备** 可停止它后续的远程访问。撤销凭据或关闭连接不是撤回已经进入执行的命令；任务若仍在运行，应另外暂停并核对。

首选同 Wi-Fi 完成第一次使用。也可在双方已配置好的私有网络上选择电脑的相应 IPv4 地址，但本项目不代办私有网络服务的账户登录、设备加入或路由设置，**跨网络实际连通未在此作保证**。同 Wi-Fi 方案不需要公网端口映射、公开临时隧道或云中转；不要把本机监听直接暴露到公网。访客 Wi-Fi、无线客户端隔离、VPN 路由、防火墙或电脑休眠都可能阻断连接。

手机凭据、草稿与请求记录使用 Android Keystore 的 AES-GCM 密封，并禁用应用备份与界面截屏。Windows 网关私钥由当前用户 DPAPI 加密保存，装载时只在受限私有目录临时解密并清理；状态目录和受控文件使用明确的 Windows 访问权限。任务记录仍不是整库加密，备份及导出内容须作为私人资料保存，不能公开上传。任务备份不包含远程凭据账本，也不能恢复手机执行权限。这些措施不保证抵抗已被完全控制的手机、电脑、管理员或同账号恶意程序。

## 不在同一个网络时

推荐用自己的 [Tailscale 私有网络](https://tailscale.com/download)，继续在其上使用本项目固定证书的 HTTPS。无需购买服务器或设置公网端口映射。

1. 在电脑与 Android 安装官方 Tailscale，两端登录你自己的同一账号；手机须亲自确认系统 VPN 请求。
2. 电脑“手机连接”里的 **异地连接检查** 只读检查客户端状态，不安装、不登录、不改路由。也可在仓库运行 `python -m relay.network`。
3. 两端显示已连接后，在电脑选其实际 `100.x.x.x` 私有地址，关闭原局域网监听，再用这个地址开启连接并按任务范围重新配对。按上面的防火墙辅助脚本只放行该地址和端口。
4. 在 Tailscale 访问策略中，只允许自己的手机访问该电脑的 TCP 8765（使用其他端口时相应调整），不要配置全网开放、出口节点或公网 Funnel。已有共享网络请让管理员设置，不覆盖原策略。
5. 手机关闭 Wi-Fi、使用移动数据测试：先读取已有结果，再发一条无文件操作的测试消息并收到回答。双端已登录、出现在线设备，都不能代替这一步验收。

Tailscale 的直连和中转使用 WireGuard 端到端加密；中转服务器转发的是密文。直连通常更快，中转性能取决于网络，不保证永远在线。[官方连接机制](https://tailscale.com/docs/reference/connection-types) · [加密机制](https://tailscale.com/docs/concepts/tailscale-encryption)

**Android 一般只能同时启用一个 VPN。** 已有代理/VPN App 时应先确认是否占用系统 VPN，不要为了连接而随意关闭有用途的安全配置。本项目不会偷偷切换 VPN。[官方兼容说明](https://tailscale.com/docs/reference/faq/other-vpns)

## 验收与故障定位

当前测试范围、版本、APK 哈希和缺口统一见[手机功能验收记录](mobile-validation.md)。主机断言、真实 Android 模拟器、合成模型响应、原生 Codex 执行和 Android 真机结果须分别判断；本指南不把其中一种替代另一种。

连接失败时按顺序检查：主管理器仍运行 → 手机连接已开启 → 使用真实本机 IP 和对应端口 → 两端网络可互通 → 防火墙规则对应当前 `python` / `pythonw` 路径 → 配对信息仍有效。证书不符时返回电脑核对身份，不允许不安全回退。排查资料只提供版本、非敏感错误和发生步骤；不要附配对文本、凭据、密钥或完整任务记录。
