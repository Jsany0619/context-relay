# Windows local manager implementation plan

Approved scope: a single-user Windows manager for Codex, retaining the standalone skill. This implements the first stage discussed with the user, not phone access or a multi-provider platform.

## Design

Python 3.10+ standard library: Tk desktop interface, SQLite durable task/event records, and a child `codex app-server` connected over stdio. No listening port, administrator service, internal Codex database edits, automatic hook trust, or desktop UI automation. Managed conversations are App Server conversations; official desktop sidebar integration is not promised.

A stable task owns successive thread IDs. Persist intent before create/start requests. Unknown outcomes are held for reconciliation, never retried automatically. Only one manager process may open the same state directory. A task retains its directory, original user messages, mode, budget, owner generation, checkpoint hash, and actual turn outcomes. A completed turn is not automatically a completed project.

The project and manager state directories must neither equal nor contain each other; operations on older task records enforce the same rule. Error handling reloads the latest persisted task before recording failures, preserving unknown intents created by an automatic summary request that times out.

The manager's SQLite ledger, drafts, and checkpoints under `%LOCALAPPDATA%\ContextRelay` are independent of the standalone skill's `CODEX_HOME/context-handoffs` files. They do not share ownership or automatically migrate state. When automatic handoff is enabled, a completed work turn with fresh context pressure of at least 70% saves a preparatory snapshot while idle; at 80% with at least two compactions, full handoff takes precedence. Manual preparation is available while idle or paused. Only the latest `drafts/<task-id>.json` is retained, containing recorded requirements/answers, the last reply, up to 20 source-turn references, file hashes, and explicit unknowns. Preparation does not invoke extra model inference or create a thread; `ready=false` makes it neither a full decision summary nor a backup. Formal handoff regenerates the summary and validates current files and READY without trusting a prior draft.

Handoff: at an idle checkpoint request a structured summary in read-only mode, hash the user requirements and referenced evidence files, start a fresh read-only receiver, require a version-bound structured READY with concrete checks, recheck the original thread and file hashes, transfer the managed owner transactionally, then continue with the original permission ceiling. Read-only summary and READY phases are expected even for workspace-write tasks; restoration requires the original instructions and permission record plus the effective native session configuration, not a permission claim in the summary. Old thread events cannot start work. Unknown operations, missing evidence, failed checks, and ambiguous creation remain blocked. The controller cannot fence arbitrary shells, MCP servers, or other clients; this is explicitly not OS-level write isolation.

First version uses a conservative permission ceiling (read-only or workspace-write, on-request human approvals). No automatic session-wide permissions, no inherited full-access mode. Read-only preparation denies approvals that would escape its sandbox. Native approvals are tied to the exact pending request and cleared when their turn ends. No credential export. App Server itself may save transcripts; manager filtering is not comprehensive DLP.

## Units and interfaces

- `relay/transport.py`: `CodexClient(command=None, cwd=None)`, `request(method, params=None, timeout=30) -> dict`, `respond(request_id, result)`, `drain_events() -> list[dict]`, `close()`. Handshake automatically; reader handles out-of-order responses; timeout is an unknown result, never an automatic resend. Exceptions `RpcError`, `RequestTimeout`.
- `relay/manager.py`: `Manager(state_dir=None, client=None)`, `create_task(title, cwd, goal, mode='read-only', auto_handoff=False, max_tokens=0, max_minutes=0) -> dict`, `start(task_id, message=None)`, `pause(task_id)`, `reconcile(task_id)`, `prepare_snapshot(task_id)`, `handoff(task_id)`, `finish(task_id)`, `answer(task_id, request_id, answer)`, `poll()`, `list_tasks()`, `get_task(task_id)`, `set_archived(task_id, archived)`, `export_task(task_id, destination)`, `close()`. Public operations serialize; polling consumes transport notifications. Task dictionaries include id/title/cwd/goal/mode/state/thread_id/turn_id/generation/last_message/error/pending/usage/context_estimate/compactions/draft/archived; older tasks may omit draft or archived.
- `relay/ui.py`: `main(state_dir=None)` uses Manager. Tk main thread only; one command worker also polls. Chinese task list, new task dialog, explicit start/continue, pause, reconcile, handoff, approvals/input, export. Closing explains interruption; no invisible unattended launch.
- `relay/__main__.py`: GUI default, `--state-dir`, diagnostic `--check`, opt-in live smoke script kept in tests.

Live tests create only disposable managed conversations and controlled local artifacts. They do not publish, commit project work, send messages, or test destructive external actions.

It is excluded from default unit discovery and stops for pending approvals/input or uncertain outcomes; a script's presence does not establish native acceptance. The usage guide provides the Windows command.

## Reliability follow-up (user selected local reliability)

Keep Python standard library, the existing permission ceiling, and separate manager/skill ledgers. Reuse the current controller and UI; do not add phone access, other providers, background services, or automatic retry of uncertain operations.

- [x] Add `Manager.prepare_snapshot(task_id) -> task` for idle/paused tasks with no unknown intent, pending approval or tool operation. Verify source idle, then atomically save a local `kind=preparatory`, `ready=false` packet containing recorded requirements/answers, last reply, up to 20 source turn references, file hashes and explicit verification gaps. Store only the latest draft per task, expose `task.draft.created_at/path/hash`, and never consume it as a final checkpoint. Fresh pressure at 70% triggers this at a completed work turn when automatic handoff is enabled; 80% plus two compactions still uses the full final-summary/READY protocol. No inference or new thread is needed for a draft.
- [x] Restore known turns by matching their exact ID in native `thread/read`, requiring a terminal turn and terminal evidence for every tracked tool ID. Missing results stay blocked. Verification receiver recovery never adopts its READY or transfers ownership. Settle elapsed time once after reliable terminal evidence; paused time must not keep increasing, while uncertain intervals are counted conservatively. Send recorded requirements, including corrections not previously sent, as context on every explicit continuation, with latest corrections taking precedence and completed actions excluded from replay.
- [x] Add a Chinese manual snapshot button and a visibly provisional snapshot timestamp; keep it disabled outside idle/paused. Test old task records without the new field and button visibility at 96/144-DPI-equivalent Tk scaling.
- [x] Write focused red/green regressions in `tests/test_snapshots.py` and `tests/test_recovery.py`; current manager suites pass 76 tests (38 controller, 5 transport, 14 UI, 7 snapshot, 12 recovery). The 71 standalone runtime and 6 installer tests were also rerun successfully, for 153 total. Coverage includes snapshot thresholds, stale draft/final separation, unknown telemetry, safe recovery, preserved corrections, automatic-summary timeout intent retention, and two-way state/project directory exclusion. Native recovery acceptance remains separate below.
- [x] Treat the start receipt separately from `turn/started`. Persist an immediate pause, wait for the matching started event, and send one interrupt. Duplicate pause/started events cannot resend; completion arriving first still leaves the task paused, records completed work once, and suppresses automatic handoff.
- [x] Add and pass opt-in `tests/live_recovery.py --run --root <new-outside-directory>`: immediate pause waits inside the product for matching native started, then acknowledged interruption, close/reopen, read-only reconciliation, explicit continuation reading a unique sentinel, and unchanged artifact. Manual preparation is `ready=false` with matching file evidence and only one `thread/read`, without new inference or threads. Pending approvals and unknown outcomes stop the test. This tests actual controlled interruption and continuation, not physical power loss or high-context pressure.
- [x] Update usage/acceptance documentation against the final test output and native report; exclude runtime records, user paths, thread IDs, and credentials from public documentation.
- [x] Complete final diff/privacy review and prepare the incremental change for the existing feature branch. Publication is verified against the remote branch SHA.

## Task organization follow-up

User selected continued practical improvements to Context Relay. Add task search/filtering, reversible local archiving of completed tasks, and a readable operation history. Reuse Tk, task JSON and the existing event ledger. No new dependencies, native conversation archival, filesystem cleanup, or remote control.

- [x] Controller: `set_archived(task_id, archived: bool) -> task` changes only a local display marker and records one event when that marker changes. Archive requires completed state without pending approvals, unknown intent, inflight tools, a receiver, or an unsettled run. Restoring never resumes work or changes the completed state, owner or permissions. Missing legacy markers mean false. Archived tasks cannot be reconciled into active state. Local organization and history access perform no native requests.
- [x] UI: case-insensitive search of title/goal/directory plus state/archive filters, using the full task cache for polling/shutdown and a separate visible selection. No matches means no actionable hidden task. Newly created tasks become visible. Preserve instruction drafts by task so filtering and delayed start receipts cannot send or clear another task's text.
- [x] History: use the existing worker and `get_task()` to show the latest 100 local events in a separate read-only window bound to the returned task. Distinguish a request, start receipt, actual start, terminal result and user acceptance. Display known event names and whitelisted status/purpose only, not raw prompts, commands, answers or arbitrary event payload. History is neither full chat nor proof of external success; reopen to refresh.
- [x] Validation: focused controller regressions for durable/idempotent archival, unsafe-state rejection, legacy records, preserved owner/files and zero RPC; Tk tests for combined filters, hidden selection, archive/restore, task-specific drafts, delayed history results and small-screen layout. Run the combined existing suites and launcher check; inspect the real Tk layout using synthetic data. No native inference is needed for these local-only features.
- [x] Update user documentation and complete diff/privacy review for publication to the same feature branch. Runtime state and synthetic preview artifacts stay outside the public repository; remote SHA is checked after pushing.

Task-organization acceptance on 2026-09-30: 90 manager tests plus 71 standalone runtime and 6 installer tests passed (167 total); launcher check passed. An actual Manager/Tk walkthrough with isolated disposable tasks verified search, local archive, history and restore, with unchanged project files and zero native requests. Windows and worker threads closed cleanly. These changes do not claim a new live native-handoff or interruption-recovery run.
